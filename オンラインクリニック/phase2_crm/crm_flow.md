# CRM設計——継続フォローの流れ

作成日：2026-05-20

> Phase 2の核心：初診で終わらせない。症状スコアの追跡と定期フォローで再診・継続処方につなぐ。

---

## 基本設計方針

| 原則 | 内容 |
|---|---|
| 症状の可視化 | AMSスコア・ISI・SMIを定期入力させ、改善を「見える化」する |
| タイミング設計 | 初診後7日・30日・90日をキーポイントとする |
| チャネル | メール（確実） + LINE（開封率重視）のどちらか選択 |
| 医師連携 | 患者のスコア変化を再診前に医師へサマリー送付 |

---

## 患者ステータス分類

```
[NEW]      初診前 / 問診完了・予約待ち
[FIRST]    初診完了・処方開始
[ACTIVE]   継続中（30〜90日プラン）
[LAPSED]   90日以上未受診
[CHURNED]  明示的キャンセル / 連絡途絶
```

---

## タッチポイント設計

### 初診前（Status: NEW）

| タイミング | 内容 | チャネル |
|---|---|---|
| 問診完了直後 | スコア結果＋受診案内 | メール |
| 予約翌日 | 診療の流れ案内・持参物 | メール |
| 予約24時間前 | リマインダー | メール / LINE |

### 初診後（Status: FIRST）

| タイミング | 内容 | チャネル |
|---|---|---|
| 当日中 | 処方内容・服用方法の確認メール | メール |
| 7日後 | 「効果を感じていますか？」症状チェック | メール |
| 30日後 | スコア再入力依頼・再診案内 | メール / LINE |

### 継続中（Status: ACTIVE）

| タイミング | 内容 | チャネル |
|---|---|---|
| 毎月1回 | 症状スコア更新リンク送付 | メール |
| 処方残量目安7日前 | 再診リマインダー | LINE |
| 90日時点 | 「3ヶ月継続おめでとう」経過報告 + 次の目標設定 | メール |

### 離脱防止（Status: LAPSED）

| タイミング | 内容 | チャネル |
|---|---|---|
| 未受診60日後 | 「体調はいかがですか？」声かけ | メール |
| 未受診90日後 | 「再診をご検討ください」 + お得情報 | メール |
| 未受診120日後 | 最終確認メール（以降は月1回のみ） | メール |

---

## スコア追跡設計

### 追跡指標（ピラー別）

| ピラー | 追跡スコア | 追跡頻度 |
|---|---|---|
| 睡眠 | ISI（7問） | 月1回 |
| 男性更年期 | AMSスコア（17問） | 月1回 |
| 女性更年期 | SMI（10問） | 月1回 |

### スコア変化アラート

- **改善**：「先月より〇点改善しました！」→ 継続動機強化
- **悪化**：「少し症状が強くなっています。再診をご検討ください。」→ 受診誘導
- **変化なし**（3ヶ月）：「症状が改善しない場合は治療の見直しが必要かもしれません。」→ 受診誘導

## 医師向けサマリー機能（Phase 2実装）

再診予約が入った際、自動で以下を生成して診察前に医師へ送付：

```
【再診前サマリー】
患者ID: XXXX
初診日: YYYY-MM-DD
前回スコア: XX点 → 今回スコア: XX点（差分: ±XX）
症状の変化コメント（患者自由記入）: ○○
服薬コンプライアンス（患者回答）: ほぼ毎日 / 時々忘れる / あまり飲めていない
次回の相談希望事項: ○○
```

## システム要件（Phase 2構築時）

- [ ] 患者の問診スコアを保存するDB（最低限：患者ID / 日付 / スコア種別 / 合計点）
- [ ] メール配信：SendGrid or AWS SES
- [ ] LINEメッセージ：LINE Messaging API
- [ ] スコア入力フォーム：Typeform or 自作（Astroページ）
- [ ] 医師向けダッシュボード：簡易的にはGoogleスプレッドシート連携でも可
